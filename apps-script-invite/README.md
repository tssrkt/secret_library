# Отправка приглашений через Google Apps Script

Почтовый сервис отправляет приглашения от имени Google-аккаунта, который владеет опубликованным Web app. Живой сценарий отправки приглашения новому Gmail-адресу и последующей регистрации приглашённого участника ранее подтверждён пользователем.

## Текущая публикация

Активная публикация — версия 52. Пользователь загрузил в редактор Apps Script локальный Code.gs; действующий URL Web app сохраняется.

Автоматический набор node --test tests/apps-script-invite.test.mjs на 18 ноября 2026 года: 93 теста прошли, 0 ошибок. Это изолированные тесты логики и не заменяет живую проверку опубликованного сервиса.

При следующих изменениях исходника создавайте новую версию deployment на том же Apps Script Web app и проверяйте отправку приглашения на тестовый адрес. Действующий URL приложения не меняйте.

## Первоначальная настройка

Эти шаги нужны только при создании нового экземпляра сервиса или восстановлении публикации:

1. Откройте https://script.google.com/ под Google-аккаунтом, от которого должны уходить письма.
2. Создайте проект Apps Script.
3. Перенесите исходный код из Code.gs.
4. Включите отображение файла манифеста и перенесите appsscript.json.
5. Запустите authorizeMailer и подтвердите запрашиваемые разрешения. Эта функция не отправляет письмо.
6. Разверните как Web app: Execute as — Me; доступ — Anyone.
7. Скопируйте URL Web app, заканчивающийся на /exec, и укажите его в настройках приложения.

## Защита и ограничения отправки

- Доступность Web app по URL не означает, что любой посетитель может отправить письмо: запрос должен содержать действительный токен вошедшего пользователя.
- Проверяются UID, подтверждённый адрес и привязка Google-провайдера.
- Перед отправкой проверяются профиль приглашающего, адресат, статус регистрации, право на приглашение и ограничения частоты.
- Идентификаторы отправок хранятся в виде хешей; повторный запрос не должен отправлять дубликат.
- Обычный участник может пригласить до 20 разных адресатов; активные администраторы освобождены от этого ограничения.
- Повторное письмо одному адресу возможно не чаще одного раза в час.
- Дополнительно действует лимит 10 отправок за скользящие 24 часа на пользователя.
- Сохраняется внешняя квота почтового сервиса Google; она зависит от типа аккаунта и может меняться.
- Токены и адреса получателей не должны записываться в журналы.

## Защита от перебора адресов

Защита реализована в серверном коде и применяется при проверке статусов адресов и при отправке приглашений.

- На один UID разрешено не более 30 новых адресных проверок за скользящие 10 минут.
- На один UID разрешено не более 100 новых адресных проверок за скользящие 24 часа.
- Адреса из собственной истории приглашений и повторная проверка того же адреса в течение 10 минут не расходуют лимит повторно.
- Лимит резервируется до чтения сведений о регистрации. Превышение отклоняется до таких чтений.
- Учёт лимита привязан к UID; общего лимита на сайт и блокировки по IP нет.
- Счётчики хранятся отдельно от пользовательских записей, а короткий кеш повторных адресов ограничен по времени.
- Если счётчик не удалось прочитать или обновить, запрос отклоняется. Защита работает по принципу fail closed.
- Для учёта лимитов не выполняются дополнительные операции с пользовательской базой данных.
- Ограничение адресных проверок действует независимо от статуса администратора и не заменяет отдельные лимиты отправки приглашений.

## Административный API

Административные запросы используют тот же endpoint. Перед выполнением сервер повторно проверяет Firebase ID token, статус администратора и требуемые права. Не ослабляйте правила доступа ради административных операций.
