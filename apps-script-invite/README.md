# Отправка приглашений через Google Apps Script

Почтовый сервис отправляет приглашения от имени Google-аккаунта, который владеет опубликованным Web app. Живой сценарий отправки приглашения новому Gmail-адресу и последующей регистрации приглашённого участника подтверждён пользователем.

## Текущая публикация

Последняя подтверждённая публикация — **версия 51**. Она соответствует исходнику до добавления защиты от перебора адресов. Локальный Code.gs теперь содержит новый ограничитель; опубликованная версия пока не обновлена. Не считать защиту действующей в production, пока не создана и не проверена новая версия deployment. Действующий URL сервиса менять не требуется.

После обновления исходника необходимо создать новую версию deployment на том же Apps Script Web app и проверить отправку приглашения на тестовый адрес. Не меняйте URL приложения.

## Первоначальная настройка

Эти шаги нужны только при создании нового экземпляра сервиса или восстановлении публикации:

1. Откройте https://script.google.com/ под Google-аккаунтом, от которого должны уходить письма.
2. Создайте проект Apps Script.
3. Перенесите исходный код из `Code.gs`.
4. Включите отображение файла манифеста и перенесите `appsscript.json`.
5. Запустите `authorizeMailer` и подтвердите запрашиваемые разрешения. Эта функция не отправляет письмо.
6. Разверните как Web app: Execute as — Me; доступ — Anyone.
7. Скопируйте URL Web app, заканчивающийся на `/exec`, и укажите его в настройках приложения.

## Защита и ограничения

- Доступность Web app по URL не означает, что любой посетитель может отправить письмо: запрос должен содержать действительный токен вошедшего пользователя.
- Проверяются UID, подтверждённый адрес и привязка Google-провайдера.
- Перед отправкой проверяются профиль приглашающего, адресат, статус регистрации, право на приглашение и ограничения частоты.
- Идентификаторы отправок хранятся в Script Properties в виде хешей; повторный запрос не должен отправлять дубликат.
- Обычный участник может пригласить до 20 разных адресатов; администраторы освобождены от этого ограничения.
- Повторное письмо одному адресату возможно не чаще одного раза в час.
- Дополнительно действует лимит 10 отправок за 24 часа на пользователя.
- Сохраняется внешняя квота почтового сервиса Google; она зависит от типа аккаунта и может меняться.
- Токены и адреса получателей не должны записываться в журналы.

## Защита от перебора адресов

- Обе операции проверки статусов и отправки приглашения требуют действительный подтверждённый токен авторизованного пользователя.
- Для каждого UID действует отдельный скользящий лимит: **30 новых проверок за 10 минут** и **100 новых проверок за 24 часа**.
- Адреса из собственной истории приглашений не расходуют лимит. Повторная проверка того же нового адреса в течение 10 минут также не расходует его повторно; это позволяет выполнить предварительную проверку и отправку без двойного списания.
- Лимит резервируется до чтения каталога зарегистрированных адресов. Запрос сверх лимита отклоняется до таких чтений.
- Обе операции проверки статусов и отправки приглашения требуют действительный подтверждённый токен авторизованного пользователя.
- Счётчики хранятся на сервере в защищённом виде с привязкой к пользователю; временные отметки повторных проверок кэшируются. Для учёта лимитов не выполняются дополнительные операции с базой данных.
- Общего лимита на сайт и блокировки по IP нет. Просмотр сайта, вход, чтение книг и доступ к библиотекам не ограничиваются этим механизмом.
- Лимит применяется к новым адресным проверкам каждого аккаунта независимо от статуса администратора; лимит в 20 приглашений остаётся отдельным правилом.

## Административный API

Административные запросы используют тот же endpoint. Перед выполнением сервер повторно проверяет Firebase ID token, статус администратора и требуемые права. Не ослабляйте правила доступа ради административных операций.
