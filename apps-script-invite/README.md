# Бесплатная отправка приглашений через Google Apps Script

Сервис отправляет приглашения от имени Google-аккаунта, который создаёт и развёртывает этот Apps Script. Firebase Cloud Functions, SMTP, Secret Manager и включение биллинга не используются.

## Настройка один раз

1. Откройте https://script.google.com/ под тем Google-аккаунтом, от которого должны уходить письма.
2. Создайте новый проект Apps Script.
3. В редакторе замените содержимое файла `Code.gs` содержимым одноимённого файла из этой папки.
4. Откройте Project Settings и включите показ файла манифеста `appsscript.json`. Замените его содержимое файлом манифеста из этой папки.
5. Сохраните проект. В списке функций выберите `authorizeMailer` и нажмите Run. Подтвердите запрашиваемые Google разрешения на отправку писем и внешние HTTPS-запросы. Эта функция ничего не отправляет.
6. Выберите Deploy → New deployment → Web app:
   - Execute as: Me (аккаунт владельца проекта).
   - Who has access: Anyone.
7. Нажмите Deploy и скопируйте URL веб-приложения, заканчивающийся на `/exec`.
8. В локальном репозитории откройте `js/config.js` и вставьте URL в `INVITATION_MAILER_URL`.
9. После проверки опубликуйте обновлённый сайт GitHub Pages.

## Защита

- Веб-приложение доступно анонимно, но не отправляет письмо только по адресу получателя.
- Apps Script проверяет Firebase ID-токен через Firebase Authentication: действительность токена, UID, подтверждённый email и привязку Google-провайдера.
- Затем он читает профиль, адрес получателя и конкретное приглашение через Firestore REST API с тем же Firebase ID-токеном. Firestore применяет действующие Security Rules; запрос к приглашению разрешён только его владельцу.
- Проверяется, что получатель ещё не зарегистрировался и не забрал приглашение.
- Идентификаторы отправок хранятся в Script Properties в виде SHA-256 ключей; повторный запрос не отправляет второе письмо.
- Ограничение уникальных получателей: по умолчанию не более 20 разных людей на обычного участника; администраторы не ограничены этим лимитом. Значение настраивается в админке, раздел «Приглашения». Повторные приглашения уже существующему получателю не увеличивают счётчик.
- Дополнительно сохраняется ограничение частоты: не более 10 отправок за 24 часа на пользователя и часовой интервал между повторными письмами одному получателю. Действует также дневная квота Google MailApp: для личного Gmail — 100 получателей в сутки на аккаунт владельца скрипта.
- ID-токены и адреса получателей не записываются в журналы. Серверные ключи и SMTP-пароли не используются. Firebase Web API key в коде — публичный ключ клиентской конфигурации, не секрет.

## Проверка

Откройте URL `/exec` в браузере: должен появиться текст о готовности сервиса. Реальная отправка проверяется из раздела «Друзья» в библиотеке после настройки URL в `js/config.js`.

Не включайте биллинг Firebase и не создавайте платные ресурсы для этого сервиса.

## Административная панель без Cloud Functions

Админка использует тот же Apps Script endpoint, что и приглашения. Для административных запросов скрипт проверяет Firebase ID token (подтверждённый email и Google provider), а затем повторно проверяет документ администратора и его права на сервере. Административный доступ к Firestore REST API работает через OAuth-токен владельца Apps Script, поэтому нельзя выдавать доступ к админке только на стороне браузера.

Для включения административного API нужны дополнительные действия владельца проекта:

1. В Google Cloud Console откройте IAM для Firebase-проекта project-071ee00e-4a4a-4a3d-95d: https://console.cloud.google.com/iam-admin/iam?project=project-071ee00e-4a4a-4a3d-95d
2. У аккаунта, который владеет и развёртывает Apps Script, должна быть роль **Cloud Datastore User** (roles/datastore.user). Не включайте биллинг и не создавайте платные ресурсы.
3. В Apps Script обновите Code.gs и appsscript.json из этой папки. Запустите authorizeMailer и подтвердите дополнительное разрешение доступа к Cloud Datastore.
4. Откройте Manage deployments → Edit у существующего Web app → выберите New version → Deploy. Сохраните тот же URL /exec, чтобы не менять js/config.js.
5. После публикации сайта войдите в админку аккаунтом tssrkt777@gmail.com. Только этот подтверждённый Google-аккаунт может выполнить первоначальную настройку superadmin; последующие входы не создают повторных записей.

Если у владельца Apps Script нет IAM-доступа к Firebase-проекту, административные операции будут отклонены. Не ослабляйте Firestore Security Rules ради админки.
