# Тайная библиотека

Полностью клиентское веб-приложение для отображения и индексации FB2-библиотеки из выбранной папки Google Drive. Текущий статус — **Stage 2 + ZIP**: приложение извлекает текстовые метаданные standalone FB2 и FB2 внутри ZIP непосредственно в браузере.

## Архитектура

- `index.html`, `css/styles.css` — статический интерфейс;
- `js/auth.js` — Google Identity Services и восстановление действующего access token из `sessionStorage`;
- `js/drive.js` — минимальный клиент Google Drive API v3, пагинация и ограниченные retry;
- `js/library-tree.js` — рекурсивный обход папок с concurrency 4 и построение плоского индекса;
- `js/library-index.js` — чтение активного индекса и отдельного checkpoint-файла в `appDataFolder`;
- `js/index-build.js` — подготовка, возобновление и финальная проверка чернового индекса;
- `js/fb2.js` — последовательное partial-чтение и XML-разбор `<description>`;
- `js/zip.js` — Range-чтение ZIP, EOCD/central directory и извлечение FB2 entry;
- `js/book-metadata.js` — общий выбор источника перед единым FB2 parser;
- `js/metadata-indexer.js` — batch-обработка с concurrency 3, отменой и checkpoints;
- `js/ui.js` — лениво раскрываемое дерево;
- `js/app.js` — сценарии первого и повторного запуска;
- `js/config.js` — Client ID и ID корневой папки.

Индекс `secret-library-index.json` имеет версию 4 и поля `rootFolderId`, `createdAt`, `updatedAt`, плоские массивы `folders[]` и `books[]`. Индексы версий 1–3 автоматически мигрируют. Версия извлечённых данных хранится в `metadataVersion`: только устаревшие записи снова становятся `pending`. Настоящая аннотация хранится в `annotation`; если она отсутствует, первые содержательные абзацы основного текста сохраняются отдельно в `preview`. ZIP-книга имеет `sourceType: "zip"`, Drive ID самого архива и `entryPath` выбранного FB2. Индекс хранится в скрытом `appDataFolder` Google Drive пользователя.

## Метаданные FB2

По явной команде «Проиндексировать книги» приложение извлекает из `<description>/<title-info>` название, авторов, жанры, язык, первую серию и номер, текст аннотации и ссылку на встроенную обложку. Сначала запрашиваются только байты `0-65535` через HTTP `Range`. Если `</description>` не найден, последовательно дочитываются `65536-262143` и `262144-1048575` без повторной загрузки предыдущих байтов. Если в `coverpage` есть ссылка на `binary` или отсутствует содержательная аннотация, standalone FB2 затем читается полностью: соответственно для извлечения картинки или формирования отдельного `preview` из первых содержательных абзацев `<body>`.

Поддерживаются UTF-8, windows-1251 и UTF-16 с учетом BOM и XML declaration. Возможные коды ошибок отдельной книги: `invalid_xml`, `unsupported_encoding`, `description_not_found`, `download_failed`, `parse_failed`. Ошибка одной книги не останавливает batch.

Во время переиндексации активный `secret-library-index.json` остаётся неизменным и продолжает обслуживать каталог. Результат каждые 50 книг сохраняется отдельно в `secret-library-index-building.json`; после остановки следующий запуск может продолжить этот черновик. Только полностью построенный, сериализованный и прочитанный обратно индекс одним запросом заменяет активный файл. При ошибке или закрытии вкладки рабочий каталог и его метаданные не меняются. Записи `ready` актуальной версии повторно не обрабатываются. «Повторить ошибки» — отдельное явное действие.

При «Обновить библиотеку» кеш считается актуальным при совпадении Drive file ID, `modifiedTime` и `size`. Новые и измененные FB2/ZIP получают статус `pending`, удалённые записи исчезают, а их обложки удаляются.

### ZIP

Для ZIP сначала читается хвост размером не более 65 557 байт, в нем ищется EOCD с учетом ZIP comment, затем читается central directory и нужный local header. Каталоги, `__MACOSX`, `Thumbs.db` и не-FB2 entries игнорируются; FB2 может находиться во вложенном пути. При нескольких FB2 используется первый и сохраняется предупреждение `multiple_fb2_entries`.

Поддерживаются Stored (method 0) и Deflate (method 8). Stored читает не более первого 1 MiB entry. Для Deflate скачивается только compressed entry, но целиком, с жестким пределом 16 MiB; распаковка идет потоком и прекращается после найденного `</description>` либо 1 MiB распакованных данных. Central directory ограничен 4 MiB. Полного скачивания ZIP как fallback нет. Если небольшой ZIP целиком помещается в обязательный хвостовой диапазон, хвостовой запрос естественно охватывает весь файл.

ZIP64, multi-disk и encrypted ZIP не поддерживаются и получают диагностическую ошибку. Также не поддерживаются RAR и 7z. Поврежденные offsets/sizes отклоняются до запроса больших диапазонов.

Управление библиотекой находится в dropdown круглой аватарки. Реальный профиль не запрашивается: используется нейтральный placeholder без дополнительных OAuth scopes. «Остановить» появляется только во время индексирования справа в status-panel.

## Настройка Google Cloud

1. Создайте или выберите проект в Google Cloud Console.
2. Включите **Google Drive API**.
3. Настройте OAuth consent screen и добавьте scopes:
   - `https://www.googleapis.com/auth/drive.readonly`
   - `https://www.googleapis.com/auth/drive.appdata`
4. Создайте OAuth Client ID типа **Web application**.
5. Добавьте authorized JavaScript origins:
   - `http://localhost:8000`
   - `https://tssrkt.github.io`
6. Вставьте полученный Client ID вместо placeholder в `js/config.js`.

Для браузерного приложения Client ID публичен. **Client secret, refresh token и другие секреты нельзя добавлять во frontend или репозиторий.** Если consent screen находится в режиме Testing, добавьте нужные Google-аккаунты как test users. Папка с ID из `js/config.js` должна быть доступна вошедшему пользователю.

## Локальный запуск

Из корня проекта запустите уже доступный Python:

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000/`. Запуск через `file://` не поддерживается. Для GitHub Pages публикуйте репозиторий из ветки `main`; относительные пути совместимы с `https://tssrkt.github.io/secret_library/`.

Публичная инструкция находится по адресу `info.html`. Настройка серверной отправки приглашений описана в [docs/email-invitations.md](docs/email-invitations.md).

## Границы Stage 2

Кандидатами книг считаются `.fb2` и `.zip` без учета регистра. Обложка уменьшается в браузере максимум до 240×320 без искажения и сохраняется отдельным WebP-файлом в `appDataFolder`; бинарные данные не попадают в основной JSON. Неиспользуемые файлы кеша удаляются. Для ZIP скачивается только выбранный FB2 entry (Stored или Deflate), а не весь архив; действуют лимиты 16 MiB compressed и 32 MiB unpacked. Зашифрованные, ZIP64, RAR и 7z не поддерживаются. Приложение не реализует читалку, offline/PWA или Changes API.

Локальные браузерные тесты находятся в `tests/fb2-tests.html`; при запущенном HTTP-сервере откройте `http://localhost:8000/tests/fb2-tests.html`.
