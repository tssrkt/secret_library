# Переключение библиотек

Без параметра URL открывается «Моя библиотека». `?library=<Firebase UID>` выбирает
отдельный каталог друга; выбор сохраняется при reload и работает с Back/Forward.
Email не используется. Вкладки друзей появляются только при активном входящем
разрешении и подтверждённом сервером опубликованном каталоге. Отсутствующий или
отозванный доступ очищает каталог и предлагает вернуться в свою библиотеку.
Поздний ответ предыдущей загрузки не может заменить текущую библиотеку.

Каждое переключение заново создаёт штатный каталог/поиск и сбрасывает запрос,
фильтры и пагинацию. Собственный индекс остаётся в Drive. Операции обновления и
переиндексации доступны при просмотре своей библиотеки; настройки папок всегда
относятся к владельцу текущего аккаунта.

## Доступ к каталогу друга

Предыдущая версия социального слоя хранила только отношения пользователей.
Приватный Drive appData-индекс другого пользователя прочитать нельзя. Поэтому
добавлена только читаемая проекция разрешённых папок в существующем Firestore:

- `sharedLibraries/{ownerUid}` — указатель на опубликованную версию, hash, число частей;
- `sharedLibraries/{ownerUid}/versions/{revision}/chunks/{position}` — части JSON.

Полный Drive-индекс не переносится и не объединяется с другими индексами. Проекция
содержит только разрешённые папки первого уровня и их потомков. Файлы непосредственно
в корне не входят в выбранные владельцем папки. Диагностика, checkpoint, access token,
настройки исключённых папок и ID приватных appData-обложек не публикуются.
Обложки чужого приватного appData недоступны — используется штатное состояние
карточки без обложки. Скачивание исходной книги по-прежнему требует доступа
текущего Google-пользователя к самому файлу Drive; социальное разрешение не меняет
Drive permissions и не даёт сайту права изменять исходные файлы.

Проекция обновляется после загрузки/успешного сохранения собственного индекса и
изменения настроек папок. При изменении настроек старый указатель сначала удаляется,
поэтому неудачная публикация не оставляет старый каталог доступным. Новые части
записываются до переключения указателя. Старые версии запрещены правилами для
получателей даже при знании их ID. Исторические части после прерванных публикаций
могут остаться в хранилище, но не доступны друзьям.

Части ограничены по размеру и записываются пакетами до десяти документов;
учтены [лимиты Firestore](https://firebase.google.com/docs/firestore/quotas).
Чтение проверяется правилами по активному входящему share; записи разрешены только
владельцу. Это отдельное ограничение от видимости вкладок в UI.

## Подключение

В текущем репозитории `js/firebase-config.js` содержит пустой публичный Web config.
Для работы с реальными друзьями нужно заполнить его данными существующего проекта,
включить Google Authentication и опубликовать обновлённые `firestore.rules` и
`firestore.indexes.json` (см. `docs/social-layer.md`). Клиентский код готов;
публикация правил в реальный проект этой задачей не выполнялась.
Владельцу нужно хотя бы раз открыть приложение после обновления для публикации
каталога. Новый сервер, Cloud Functions и зависимости для вкладок не добавлялись.

## Проверка

`node tests/search-keyboard.mjs` проверяет собственный каталог по умолчанию,
изолированный поиск, URL/reload, отзыв доступа, поздние ответы, клавиатуру,
overflow, правило пяти скрытых вкладок, раскрытие/сворачивание, настоящее
перетаскивание мышью и touch swipe через Chrome DevTools Protocol.
Снимок мобильной панели: `temp/library-tabs-mobile.png`.

`npm.cmd run test:social` запускает Firestore emulator: проверяет запрет чтения
без входящего доступа, ограничения чужой записи, фильтрацию папок, отзыв доступа
и запрет чтения старой версии. В этой Windows-среде Java 21 находится в
`temp/social-java/jdk-21.0.12.1+1-jre/bin`; её нужно добавить в PATH для запуска.
