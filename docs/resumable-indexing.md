# Возобновляемая индексация

Google access token обновляется за минуту до истечения и по требованию Drive. Одновременные запросы используют один запрос GIS с `prompt: ''` и известным `login_hint`. При 401 исходный запрос повторяется один раз. Обычный 403 остаётся ошибкой доступа; ограничения частоты обрабатываются существующим механизмом повторов. GIS может потребовать действие пользователя или заблокировать popup: приложение показывает «Подключить Google снова», сохраняя библиотеку и операцию. См. [справочник GIS](https://developers.google.com/identity/oauth2/web/reference/js-reference).

В IndexedDB `secret-library-indexing` хранятся рабочий индекс и локальный журнал результатов. Ключ включает email подтверждённого Drive-пользователя и корневую папку. Manifest содержит тип операции, исходную сигнатуру (версии индекса/метаданных, папка, timestamp и число книг), выбранные и обработанные ID, прогресс и ошибки. Оставшаяся очередь определяется по выбранным книгам со статусом pending/processing. Credentials в эту базу не записываются; существующее хранение действующего access token ограничено sessionStorage.

Перед обработкой записывается исходный checkpoint. Каждый завершённый пакет (обычно три книги) атомарно сохраняет изменённые записи и manifest; большой основной индекс при этом в Drive не отправляется. При аварийном закрытии возможна повторная работа только над последним ещё не зафиксированным пакетом. Временные ошибки сети и авторизации оставляют файлы pending и ставят операцию на паузу. Ошибки отдельных файлов записываются в существующий отчёт, остальные файлы продолжают обрабатываться; повтор ошибок остаётся отдельной командой.

После переподключения в открытой странице операция продолжается автоматически. После reload предлагается «Продолжить индексацию — осталось N». «Обновить библиотеку» сначала продолжает существующую очередь. Полная переиндексация не заменяет незавершённое обновление. Checkpoint другого пользователя не загружается; несовместимый с текущим индексом отбрасывается перед обычным обновлением.

Завершение использует существующий рабочий файл Drive, затем запись основного индекса и его чтение для проверки результата. Локальный checkpoint удаляется только после успешной записи и совпадения прочитанного содержимого. Ошибка сохранения/проверки сохраняет возможность повторить финализацию без обработки книг заново. Локальное восстановление относится к тому же браузерному профилю; очистка данных сайта удаляет IndexedDB.

Проверка: `node tests/search-keyboard.mjs`. Помимо регрессий интерфейса и форматов, тесты моделируют параллельные 401, отказ GIS, 403, очередь 1535 из 9336, сохранение 1000 и продолжение 535, полную обработку 9336 и ошибки финального сохранения. Отдельная fixture запускает настоящий app.js с подменой только внешних Drive/GIS/Firebase: выполняет реальный reload, отказ обновления токена, проверку сохранения авторизованного интерфейса и автоматическое продолжение после подключения. Реальный Google popup в автоматических тестах не открывается.
