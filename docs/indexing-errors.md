# Диагностика 416/404 при индексации

## Что установлено по коду и воспроизведено тестами

До исправления самостоятельный FB2 всегда начинал загрузку с `Range: bytes=0-65535`,
затем при необходимости запрашивал `65536-262143` и `262144-1048575`.
Размер из записи книги в этот алгоритм не передавался. Если описание не было найдено,
файл заканчивался ровно на границе диапазона и `Content-Range` был недоступен,
следующий запрос начинался за EOF и получал 416. Тест воспроизводит это на 65536 байтах.

ZIP читает хвост начиная с `book.size - 65557`. Если размер в индексе устарел и файл
уменьшился, начало хвоста может оказаться за фактическим EOF. Это также воспроизведено
тестом: после 416 полная загрузка и разбор с новым размером успешны.

Диапазоны вычисляются вручную; у каждого чтения собственные headers и локальный кеш.
Общего сохранённого offset, переноса Range между файлами или resume скачивания нет.
Возобновление индексации работает на уровне книг. Ранее ответ 200 на второй Range
мог ошибочно добавляться к уже загруженному префиксу; теперь он заменяет префикс.

Неверный Content-Range с несовпадающим началом или длиной теперь отклоняется.
Для больших FB2 известный размер ограничивает запросы. Для FB2 до 1 МиБ или с
неизвестным размером используется одна полная загрузка без Range: из тех же байтов
получаются метаданные, существующие annotation/preview и обложка. Для больших
аннотированных FB2 без обложки и для ZIP частичное чтение сохраняет экономию трафика.

**Причина конкретного пользовательского запроса пока не подтверждена:** исходные
fileId, Range, Content-Range и размер файла не предоставлены. Две ошибки 404 также
нельзя достоверно объяснить удалением или потерей доступа только по HTTP-коду.
Ранее FB2-обёртка теряла status, а сообщение любого 404 ошибочно называло корневую
папку. Теперь status и этап сохраняются, сообщение относится к конкретному файлу.

## Повторы и сохранность данных

- 404: без повторов.
- 416: одна новая полная загрузка без Range, без внутренних повторов этого запроса.
  Для ZIP весь разбор запускается заново по полученным байтам и фактическому размеру.
- 429, 500/502/503/504, сетевые ошибки: максимум три попытки с backoff.
  Ограничение времени запроса — 30 секунд; Retry-After ограничен 10 секундами.
- Ошибка файла записывается и не мешает другим книгам. Истечение общей авторизации
  остаётся прерыванием с сохранением черновика. Завершение параллельной пачки ожидается
  перед checkpoint, чтобы книги не изменялись после сохранения черновика.
- При ошибке переиндексации прежняя ready-запись копируется целиком из активного индекса.
  Даже её metadataVersion не подменяется. Проверка готовности допускает такую старую
  версию только для записи с соответствующей ошибкой и точным совпадением с прежней.
  Кнопка повторения ошибок учитывает и такие сохранённые записи.
- Рабочий индекс не изменяется в процессе построения. Перед существующим переключением
  проверяется полнота списка книг и сохранность записей. Ошибки index-write видны в журнале.

## Журнал

`indexingErrors` хранится отдельно от метаданных книг на верхнем уровне чернового индекса,
попадает в обычные checkpoints и в завершённый индекс. Дополнительных запросов для
записи или просмотра журнала нет. При невозможности сохранить checkpoint журнал остаётся
доступен в памяти вкладки для копирования/скачивания.

На файл создаётся одна запись результата; `events` содержит историю отдельных ошибок
запросов, их timestamp, stage, HTTP status, code, message, attempt, Range, Content-Range
и retryResult. Сохраняются fileName, fileId, outcome и previousEntryPreserved.
Authorization, токены, заголовки авторизации и stack trace в журнал не включаются.

`outcome=failed` соответствует счётчику окончательных ошибок файлов.
`outcome=recovered` показывается отдельно как «Восстановлено повтором», не увеличивая
число неудачных книг. `interrupted` — отдельное прерывание общей операции.
Таким образом, повторные сетевые ошибки одной книги не умножают счётчик ошибок файлов.
Журнал доступен через «Показать», «Скопировать ошибки» и «Скачать лог» в блоке статистики.
При запрете Clipboard API отображается выделяемый текст для ручного копирования.

Этапы: list, metadata, download, parse, metadata-extraction, annotation, preview,
cover, index-write. Журнал получает только ошибки операций индексатора, а не глобальные
события console/fetch. `favicon.ico 404` и ошибки отображения страницы туда не попадают.

## Проверка

`tests/indexing-errors-tests.js` подключён к `tests/fb2-tests.html` и проверяет успешное
чтение, оба исхода retry 416, 404, исчерпание backoff 503/network, восстановление 429,
устаревший размер ZIP, границу FB2, Content-Range, этапы parse/cover, сохранение старой
записи и проверку её целостности, продолжение после ошибки, исключение favicon и UI журнала.

HTTP-семантика сверена с [RFC 9110, раздел 14](https://www.rfc-editor.org/rfc/rfc9110.html#section-14).
Использование Range для blob-файлов Drive описано в [документации Google Drive](https://developers.google.com/workspace/drive/api/guides/manage-downloads).
