**Дата проверки:** 18 ноября 2026 года
**Рабочая ветка:** main
**Коммит на момент начала аудита документации:** bdd03d8
**Apps Script Web app:** версия 52 (пользователь подтвердил загрузку локального Code.gs в редактор Apps Script)

## Краткий статус

Проект работает в ветке main. Документация синхронизирована с подтверждённой версией почтового сервиса, реализованной защитой и результатами проверок.

Защита от перебора адресов реализована в серверном обработчике проверки статусов и отправки приглашений:

- на один UID — не более 30 новых адресных проверок за скользящие 10 минут;
- на один UID — не более 100 новых адресных проверок за скользящие 24 часа;
- повторная проверка того же адреса в течение 10 минут и адреса из собственной истории приглашений не расходуют лимит повторно;
- лимит резервируется до чтения сведений о регистрации;
- если сервер не может обновить счётчик, запрос отклоняется (fail closed);
- общий лимит на сайт и ограничение по IP не реализованы.

Ограничитель не меняет лимиты отправки приглашений: 20 уникальных адресатов для обычного участника, без этого ограничения для активных администраторов, повторная отправка одному адресу не чаще раза в час и дополнительный лимит 10 отправок за 24 часа на отправителя.

Версия 52 содержит локальный Code.gs, загруженный пользователем в Apps Script. Автоматические тесты подтверждают логику исходника, но не заменяют живую проверку сервиса с реальным Google-аккаунтом.

Это ручные проверки, выполненные пользователем в более ранних сессиях. В рамках текущего аудита повторная проверка этих сценариев на production не выполнялась.

## Результаты автоматических проверок в текущем аудите

| Набор | Результат |
| --- | --- |
| Полный Node-набор с Firestore Emulator | 229 тестов: 227 прошли, 0 ошибок, 2 пропущены |
| Apps Script | 93 теста: 93 прошли, 0 ошибок |
| Браузерный smoke (tests/search-keyboard.mjs) | 233 прошли, 1 провалился |
| Playwright E2E | Не запущен: порт 4173 уже занят другим процессом |
| git diff --check | Ошибок нет |

Два пропуска полного Node-набора относятся к проверкам, которым нужны отсутствующий ограниченный ключ Google Picker и живая Google Drive OAuth-сессия. Они не являются падениями тестов.

Единственный провал браузерного smoke — проверка «success shows the exact root-folder access instruction» в tests/social-ui-tests.js. Проверка ожидает прежний точный текст успешной отправки приглашения. Это реальный провал тестового набора, и его причину следует отдельно сверить с актуальным пользовательским текстом; он не скрывается под формулировкой «все тесты прошли».

Playwright не дал результата: тестовый сервер не стартовал, потому что http://127.0.0.1:4173/ уже занят. Существующий процесс не останавливался.

Команды для повторения:

    .\node_modules\.bin\firebase.cmd emulators:exec --project demo-secret-library --only firestore "node --test tests/*.test.mjs"
    node --test tests/apps-script-invite.test.mjs
    node tests/search-keyboard.mjs
    npm.cmd run test:e2e

Команда npm.cmd используется в PowerShell, чтобы обойти блокировку npm.ps1 политикой выполнения сценариев. Не меняйте ExecutionPolicy ради запуска тестов.

## Социальная модель и доступ

- Входящие и исходящие разрешения независимы: доступ не становится взаимным автоматически.
- Входящий доступ подтверждается чтением корневой папки друга в Google Drive; исходящий — текущими разрешениями на корневой папке владельца.
- При каждой перерисовке списка друзей состояния доступа проверяются заново через Google Drive. Кешированные ID корневых папок — только кандидаты для проверки, а не доказательство доступа.
- Если проверка не удалась, статус остаётся неподтверждённым; интерфейс не должен подменять ошибку проверки крестиком.
- В опубликованный каталог входят только разрешённые владельцем папки и их потомки; файлы непосредственно в корне не добавляются автоматически.
- Уведомления относятся к новым обнаруженным входящим разрешениям, а не ко всем существующим отношениям. Отзыв и последующее восстановление доступа создают новое событие.
- После принятия приглашения связь с пригласившим восстанавливает исходящую строку друга; обратный доступ при этом не предполагается.
- Смена корневой папки перемещает и обновляет существующий файл каталога, не создавая второй файл и не удаляя файлы Drive.

## Публикация и релиз

Публичный адрес приложения: https://tssrkt.github.io/secret_library/.

В рамках этого аудита не выполнялась новая проверка GitHub Pages deployment и не проводилась полная ручная проверка production в браузерах. Пользователь отдельно подтвердил ручную работу кнопок «ПОДЕЛИТЬСЯ» и «ОТМЕНИТЬ» на странице настроек. Наличие успешных локальных тестов не доказывает готовность остальных production-сценариев.

Перед объявлением релиза остаётся:
1. Разобрать единственный провал браузерного smoke и привести тест/интерфейс к согласованному ожидаемому поведению.
2. Повторить Playwright E2E после освобождения или корректного переназначения занятого тестового порта.
3. Провести короткую ручную проверку Google OAuth, Picker, отправки приглашения, проверки доступа и открытия чужой библиотеки на актуальной публикации. Кнопки «ПОДЕЛИТЬСЯ» и «ОТМЕНИТЬ» уже проверены пользователем и повторно в этом пункте не требуются.
4. Повторить все затронутые проверки на итоговом коммите.

## Правила дальнейшей работы

- Работать только в main.
- Перед изменением кода читать локальные .ua/knowledge-graph.json и .ua/architecture-report.md, показывать затронутые модули и план проверки и получать явное подтверждение.
- После согласованного изменения кода запускать соответствующие тесты, коммитить и отправлять изменения в main.
- Документацию можно обновлять без изменения кода приложения.
- .ua/knowledge-graph.json, .ua/architecture-report.md и промежуточные результаты анализа остаются локальными и не включаются в коммиты.
